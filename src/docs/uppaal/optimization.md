# Optimization with UPPAAL

Generated by `node optimize.js` (src/docs/uppaal). For each parameter, UPPAAL (`verifyta`) is asked by bisection
for the largest or smallest value for which the listed queries stay satisfied. This shows how much room the
design values have: the **margin** is the distance between the value used and the value UPPAAL still accepts.
All other parameters keep the values of the models (estimated ones are marked in the model files).

## What each line means

- **Supervision: how slow may a Docker restart be?** Largest restart time for which a node is back within 60 s (THM-REQ-73) and MON never escalates to Maintenance (45 s). The code assumes at most 30 s.
- **Supervision: how late may the broker declare a node dead?** Largest detection time that still meets the 15 s of THM-REQ-72. The broker gives 7.5 s (1.5 x keep-alive of 5 s), so the keep-alive could be up to this / 1.5.
- **Batter: smallest safe batch-lost limit of dosing** Smallest limit after which dosing may give up a batch without ever dropping one that is still being made or deposited. The code uses 120 s.
- **Batter: largest wait T_batter** Largest batter wait for which the LOST limit of 120 s still holds, with one UC4 rejection. The group fixed 25 s from food safety, not from this bound.
- **Batter: longest stop of depositing** Longest stop of depositing (estimated at 60 s) for which even a discard at depositing happens before dosing gives the batch up. A negative margin is not a failure: at the estimated 60 s the late discard (126 s after the batch started) comes after dosing gave up, so it only drops a batch dosing already replaced; nothing is deposited from it (the Took query holds for any stop length).
- **PLM: largest restock time** Largest Logistics restock time for which BAT still gets its final answer before it repeats the request after 20 s (with the withdrawal of 3 s).
- **PLM: smallest BAT retry time** Smallest retry time of BAT that is longer than the final answer (restock 15 s + withdrawal 3 s). The code uses 20 s.
- **Handover: largest reconcile period** Largest scan period for which a stored document is taken up within 8 s (TIM-06) with a grace of 3 s.
